# 轻量聊天记忆改造实施记录

日期：2026-10-07。项目：Morrow（暮伴），版本：0.4.0-evidence-memory。起点为 0.3.15；设计依据为旧项目的「29-轻量聊天记忆系统改造方案-2026-10-05.md」。

## 规划与实施顺序

| 阶段 | 工作 | 交付 |
| --- | --- | --- |
| A：事实安全 | 证据类型、时间、适用性、版本补丁、删除 | MemoryPolicy / MemoryLifecycle |
| B：整理可靠性 | 持久任务、合并、领取、暂停、恢复、重试 | MemoryRepository / MemoryJobRunner |
| C：归纳与溯源 | 有依据的归纳、依赖失效、后台查看 | MemoryConsolidator / 管理后台 |
| D：压缩与续发 | 摘要条目、增量合并、原文回查、预算恢复 | SummaryService / ChatService |
| E：验证交付 | 合成数据回归、构建、隔离桌面验收、文档 | 测试与实施记录 |

保留用户输入与双方聊天两份原文、现有 LangChain 传输、全部角色人设及长期记忆输入政策。没有导入 Hindsight，也没有引入 Python 服务、向量库、知识图谱或通用 Agent 框架。原项目源码副本不改；本次不打开用户真实数据库，不使用真实模型额度。真实数据库升级在运行新版时执行。

## 内容分层

- 用户原文：user_inputs，保留输入文本、来源 message_id 和所属会话；与 messages 的用户消息原子同步。
- 完整聊天：messages，保留双方文本、角色、状态、时间和图片关联；新增 revision、turn_id。
- 人工资料：memories，用户明确录入或确认的文字，具有版本、范围和生命周期。
- 自动来源事实：conversation_memories，模型从确切原文抽取的自述、偏好、经历、计划、主观相信等，保留 memory_sources 和批次。
- 归纳理解：memory_observations，通过 memory_links 引用确切事实/人工资料及版本，不作为独立证据。
- 会话摘要：session_summaries 是可读快照，summary_entries 是具有稳定 ID、模态、范围和出处的条目。有损压缩，不替代原文。

用户自述不等于外部核实；模型推断不等于用户确认；角色主观相信不等于客观发生。新的现实用户事实或共同经历必须至少引用用户原文，助手单独引用只允许显式的角色主观相信。

## 数据库结构

schema 12。保留原表和外键，新增以下六张表：

| 表 | 主要字段 / 含义 |
| --- | --- |
| memory_events | ID、target_type / target_id、operation、revision、source_ids、created_at；仅操作元数据，不保存正文前后快照 |
| memory_jobs | kind、角色/会话/角色版本、generation、history_revision、state、attempts、not_before、lease_until、run_token、payload、error_code |
| memory_observations | 角色/会话/角色版本、scope、topic_key、text、status、revision、author、创建/更新时间 |
| summary_entries | 会话、category、text、scope、modality、status、revision、author、source_granularity |
| memory_links | target_type / target_id → source_type / source_id / source_revision，承载归纳与摘要的依赖 |
| memory_suppressions | 角色/会话、原文 message_id、fact_key、创建时间，阻止删除后由旧出处重新提取 |

原表新增 sessions.memory_generation；messages.revision / turn_id；两类事实的 metadata、lifecycle_change_id；memories.scope / session_id；memory_changes.previous_change_id。原文图片不重复复制到记忆表。

事实 metadata 区分 user_asserted、user_confirmed、fiction_event、character_belief、hypothesis、quoted、model_inferred，允许 assertedAt 和 validityBasis。生命周期保留 status、factKey、changeType、eventTime、validFrom / validTo、conditions、dependsOn 或带 revision 的 dependencies。未返回字段保留；有确切新增证据时通过 clearLifecycleFields 显式取消旧字段。

更新关联包含来源消息 ID、原文哈希、角色版本、依赖 ID / revision、补偿链。版本单调递增，撤回不会倒退版本号；有更新令牌的补偿不会覆盖后来的人工修订。

升级前对旧库执行 SQLite VACUUM INTO 一致性备份，包含 WAL 中已提交内容。备份在同一数据目录，后缀 .sqlite.bak。遇到比程序更新的 schema 明确拒绝；迁移出错回滚。测试验证原文双存仍完整。备份不会随“删除记忆”自动清理，用户应按自己的保留策略管理备份和导出。

## 当前适用性

程序计算 applicability，不能只看存储的 active：

- validFrom 尚未来到 → future；validTo 已结束 → expired。
- 旧的模糊日期或损坏元数据 → unknown / needs_review，保留正文供检查。
- 计划、假设、引用和模型推断不能当作已确认现状。
- 无截止时间的临时状态 → unknown。
- 未验证自然语言条件 → needs_review。
- 依赖被删除/越域/不再适用 → condition_failed；依赖版本改变 → needs_review；循环拒绝写入。
- 其余通过检查的 active 才是 current。

新的时间必须为 ISO 日期或带时区的 ISO 时间，拒绝非法日期和依赖本机语言环境的字符串。日期采用 UTC 日期边界；精确本地时间应带 +08:00 等时区。此版没有时间区间对象、日期精度字段或自然语言条件执行器。

例如上海搬到北京：抽取模型根据用户原文提出新北京记录与旧上海的 historical 补丁；路线若依赖旧常住地，程序立即判不适用；未说明改变的工作地点由模型标记待核实；地铁偏好无此依赖则保留。迁移、纠错、短期出差、未来计划和剧情由模型判断类别，程序校验证据、作用域、版本、时间和依赖。关键词仅用于优先调度，不决定语义，也不声称程序已能验证文本蕴含关系。

## 写入与任务调度

用户输入立即保存；当前回复直接看本轮原文，明确纠正不必等待后台抽取才能被模型采用。旧人工正文不会自动改写，生命周期可依新用户证据调整。

普通抽取按约 45 秒空闲窗口合并；至少六条新增用户原文立即处理；明确搬家/纠正词句约 1.5 秒后优先。有变化再合并约两分钟后的归纳任务。自动摘要/自动长期记忆默认开启，用户关闭后自动任务不领取，不累计无效尝试；手动整理仍可执行。部分设置保存保留已有开关，不重置用户选择。

任务状态：queued → running → succeeded；短暂失败进入 retry_wait，5 秒 / 30 秒退避，最多三次后 blocked。鉴权失败、不可用接口或不合法输出不盲目重试；后台可手动重试。暂停不是失败，返回等待状态；正常退出释放租约，异常退出在 15 分钟租约到期后可重新领取。超时上限为当前配置，最大 10 分钟。暂无多进程任务平台、租约续期或复杂重试抖动。

任务按角色、会话、兼容版本和 generation 合并；结果写入、批次游标、下一批任务和完成状态在同一事务。旧执行令牌、旧会话版本和旧快照不能提交。切换会话/角色时，有效后台归档仍属于原会话；角色无法加载或版本改变的任务进入需处理。

## 归纳、删除与人工修订

归纳只引用当前适用的事实/人工资料与确切版本。同主题增量更新，未变化条目保留；人工编辑后的正文不自动覆盖。来源修改或删除即标记关联归纳待核实，注入前还会再校验依赖状态和版本。

删除来源事实会移除正文和来源关联，并记录出处 + factKey 抑制；无稳定主题时保守抑制该条原文的全部记忆抽取。相同旧出处不会轻易重建删除条目。删除归纳抑制相同主题和相同证据版本的重建，新证据版本允许重新形成理解。此版不是语义级黑名单，主题被模型换名仍存在规避风险。

记忆修订/事实状态变化使同角色摘要快照及条目失效，防止旧城市等从派生摘要再回来；这是保守清理，可能比需要的范围更大，原文不删。删除记忆不等于删除聊天原文，模型仍可能在保留历史中读到该内容。

现实资料限同角色共享，fiction / unknown 再绑定会话。后台新增人工记忆支持选择范围和按会话名搜索绑定。不同角色不自动共享；当前没有独立于会话的世界线 ID，分支使用不同会话隔离。

## 压缩策略

正常聊天优先使用可容纳的完整原文。达到约 75% 预算可后台整理旧历史；请求超预算而旧历史可压缩时先整理、再自动继续已保存的当前问题。同问题因上下文失败重试复用原用户消息，避免重复入库。

保留最近四条用户轮次原文，压缩批次最多读取 480 条消息，再按实际整理请求预算缩到完整用户轮次，不截断单条消息。批次上限是作业粒度，可多批推进，不是总历史/长期记忆截断。单轮或全量基础资料仍超预算时明确失败并保留原文，不继续无效压缩。

摘要条目保留七类分类、real / fiction / unknown、asserted / possible / negated / conditional、active / resolved、author、revision 和 exact / batch 出处。同主题可合并，保留主 ID、全部被合并来源及最新用户依据。人工整体编辑无法自动确定每句原文，所以标记 batch。兼容旧数组协议也只标 batch，不伪造精确出处。

每五版尝试从覆盖的原始消息重新生成自动条目，并保留人工条目；只有完整覆盖原文处于当前批次范围且能放入一个整理请求时执行，否则继续增量整理。没有实现任意长度全历史的分层重建。摘要不宣称无损，细节可沿来源在后台回查；原文保留至用户主动删除。

摘要每项最多 720 字，各分类数量有压缩产物上限，总 JSON 最多 15000 字符；超过拒绝，模型应合并内容，程序不静默 slice。摘要不是无限累计的第二份原文。核心设定、提示词、人工记忆和自动事实无新增条数/正文限制，全部当前作用域资料仍按原政策提供，包括有明确历史/过期标签的条目。模型窗口与输出预留继续约束总请求。

归纳仅注入依赖仍当前有效的项。模型收到摘要条目的范围/模态/作者等标记，原始出处链接在数据库和后台保存。低优先级资料不作为系统指令执行；提示约束不等于能彻底消除模型误读。

## 管理后台与调试

保留独立 Ant Design 管理窗口、会话名称、搜索、分页与用户原文会话筛选。自动长期记忆增加来源事实 / 归纳理解切换、生命周期筛选、当前适用性说明。归纳详情可点击查看依据，随后回查原始对话；摘要条目可逐项查看出处。

概览显示最近 100 个任务，包含会话名、状态、次数、安全错误码与重试入口。仅查看不调用模型。传给页面的任务字段不含执行令牌和内部任务 payload。

请求诊断冻结请求开始时的人工/事实/归纳 ID 与版本、角色兼容版本、完整提示版本和摘要版本，避免后台变化后错报“本轮用过哪些资料”。不记录私密正文或密钥。

角色 manifest 可选 memoryCompatibilityVersion：不填时使用完整设定哈希严格隔离；填写时作者明确承诺设定兼容，身份/世界线变化必须换版本，不由程序猜测。

## 性能与后续边界

当前仍为 Electron 主进程中的同步 SQLite 单写入者。来源与图片元数据改为批量读取，管理页适用性计算复用，token 估算增加分块缓存；没有完成数据库/token 估算 worker 化，不承诺唯一文本组成的百万上下文不会产生主线程延迟。下一步应先用有授权的长文本采样测量，再决定 worker。人工归纳若依据变更后待核实，仍需检查依据；编辑正文不自动证明旧依赖仍有效。

此版不做 RAG、向量/关键词检索融合、跨角色共享画像、通用知识图谱、外部工具任务或周期性人格评估。不使用每轮第二次“审判模型”校验所有语义；格式/出处/版本/时态由程序兜底，语义与抽取完整性仍取决于配置模型。全量已有资料超预算时仍显式报错，没有暗中改回 top-K。
